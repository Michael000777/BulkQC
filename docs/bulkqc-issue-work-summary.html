Issue #3: Add export option for raw count distribution histogram

Merged to main

Branch: export-count-distribution-html | Commit: 69e60d0 | Main merge: 456a90f

The Export tab already allowed users to download the QC table, PCA plot, and QC metric histogram. The QC Overview tab also showed a raw count distribution plot, but that plot could not be exported. This made the app inconsistent: users could inspect the plot in the app but could not share it later.

What changed

  • Added a new Export checkbox: Raw count distribution (HTML).
  • Reused the existing qc_bundle$count_dist() reactive from the QC module.
  • Saved the selected plot into the ZIP as count_distribution.html.
  • Added a focused test that confirms the new UI option exists.

Why this matters

A QC app should make review artifacts easy to share. Exporting the same plots that users inspect in the interface reduces screenshots, manual copying, and ambiguity in team reviews.

How to review manually

  1. Run the app and upload the sample counts and metadata from BulkQC/inst/extdata.
  2. Open the QC Overview tab and confirm the raw count distribution plot renders.
  3. Switch between All counts and One Sample.
  4. Open the Export tab, select Raw count distribution (HTML), and download the ZIP.
  5. Confirm the ZIP contains count_distribution.html and that it opens outside Shiny.
Learning point: This is a good example of a small, low-risk feature. It uses an existing reactive instead of adding duplicate plotting logic, which keeps behavior consistent between the app view and the export.

Issue #4: Add tests for export bundle contents

Merged to main

Branch: issue-4-export-tests | Commit: 69f91e5

The export workflow is user-facing and easy to break by changing labels, filenames, or validation text. Issue #4 adds more structure around those values so tests can check the export contract directly.

What changed

  • Factored export option IDs and labels into bulkqc_export_options().
  • Factored default selections into bulkqc_export_default_options().
  • Factored export filenames into bulkqc_export_filenames().
  • Factored unavailable-artifact messages into bulkqc_export_unavailable_message().
  • Expanded test-export.R to check labels, option IDs, defaults, filenames, and error handling.

Why this matters

Tests are strongest when they protect behavior that users depend on. For exports, filenames and option IDs are part of the app contract because downstream users may save, email, or script around those files.

How to review the code

  1. Check that the helper functions are small and return plain values.
  2. Check that the UI and server use the helpers instead of repeating strings.
  3. Run Rscript -e 'setwd("BulkQC"); testthat::test_local()'.
  4. Confirm the tests fail if an export filename or option ID is changed accidentally.
Learning point: Pulling repeated constants into helpers is useful when those constants are tested and reused. The goal is not abstraction for its own sake; the goal is to make the export contract visible and testable.

Issue #2: Include selected QC settings in exported HTML artifacts

Merged to main

Branch: issue-2-export-metadata | Commit: 3780bcb

Before this change, exported HTML plots contained the plot itself but not the settings that produced it. That can be confusing later because a reviewer may not know which PCA color factor, histogram metric, bin count, sample, transform, or subsampling limit was used.

What changed

  • The PCA module now returns pca_settings, including the selected coloring factor.
  • The QC Overview module now returns settings for the QC metric histogram and count distribution plot.
  • The Export module prepends a visible metadata header to exported Plotly HTML files.
  • The header includes the plot title, export timestamp, and selected settings.
  • Tests cover the metadata header and optional metadata evaluator.

Why this matters

Exported artifacts often outlive the Shiny session that produced them. Including settings in the HTML file makes each artifact more self-explanatory and easier to review in a team setting.

How to review manually

  1. Run the app from main.
  2. Upload sample data and change the PCA coloring factor or histogram settings.
  3. Export the PCA or histogram HTML files.
  4. Open the exported HTML and confirm a BulkQC metadata block appears above the plot.
  5. Confirm the metadata matches the current UI selections.
Learning point: Reactive modules should return the information other modules need, not reach across module boundaries. Returning settings reactives keeps the Export module decoupled from the internals of the PCA and QC modules.
